1. The Big Picture

What is a Chrome Extension?

A Chrome Extension is like a small app that lives inside your web browser. It can add buttons to pages, watch what you do, save data, and show you information — all without touching the internet.

🏠 Think of it like this: Chrome is your house. Zendesk is a room inside. A Chrome extension is like a tiny helper you placed in that room — it can see that room, press buttons there, and write notes. But it stays quietly in the corner unless you call it.

The 3 Worlds of This Extension

These three worlds cannot directly touch each other's code. They communicate by sending messages — like texting between people in different rooms.

3. manifest.json — The ID Card

📋 Analogy: Imagine you're starting a new job. HR gives you a form: What's your name? What rooms can you enter? What's your role? manifest.json is exactly that form — Chrome reads it the moment you install the extension.
JSON
// Chrome reads this file FIRST. It tells Chrome everything. { "manifest_version": 3, // Must be 3 (the modern standard) "name": "Zendesk Ticket Tracker", // Extension name shown in Chrome "permissions": ["storage", "activeTab"], // "storage" = can save data on your computer // "activeTab" = can see which tab is open "host_permissions": ["*://*.zendesk.com/*"], // Only runs on Zendesk pages — nowhere else! "background": { "service_worker": "background.js" }, // This file runs silently in the background always "content_scripts": [{ "matches": ["*://*.zendesk.com/*"], "js": ["content.js"], // Inject this JS into Zendesk "css": ["widget.css"] // Inject this CSS into Zendesk }], "action": { "default_popup": "popup.html" } // When user clicks the TT icon → open popup.html }

Key Concepts

Manifest V3

  • The current Chrome standard
  • Uses "service workers" not "background pages"
  • More secure by design
  • Extensions must declare all permissions upfront

host_permissions

  • *://*.zendesk.com/*
  • The * means "any" (http or https)
  • *.zendesk.com = any subdomain
  • e.g. yourcompany.zendesk.com

4. background.js — The Brain

🧠 Analogy: background.js is like a secretary who works in a back office with no windows. You (the widget) shout through the wall: "Save a red ticket!" The secretary writes it in a logbook and shouts back "Done!" The secretary never sleeps — always ready to receive messages.

The Storage Format

All data is saved in chrome.storage.local — the browser's built-in safe box. It never deletes unless you tell it to. The data looks like this:

JSON (stored data)
{ "events": [ { "type": "open", "timestamp": 1709100000000 }, { "type": "new", "timestamp": 1709100060000 }, { "type": "team", "timestamp": 1709100120000 } ], // ↑ Every double-click adds one entry here. Never deleted. "dailyTotals": { "2026-02-28": { "open": 5, "new": 3, "team": 2 }, "2026-02-27": { "open": 8, "new": 1, "team": 4 } } // ↑ Fast lookup by date. Updated every time an event is added. }

How dateKey() Works

Every event gets a date key — a string like "2026-02-28" — so we can group tickets by day.

JavaScript
function dateKey(ts) { // ts = timestamp (milliseconds) const d = new Date(ts); // Convert ms → readable date const y = d.getFullYear(); // e.g. 2026 const m = String(d.getMonth() + 1).padStart(2, '0'); // e.g. "02" const day = String(d.getDate()).padStart(2, '0'); // e.g. "28" return `${y}-${m}-${day}`; // → "2026-02-28" }

Listening for Messages

JavaScript
// This runs whenever content.js or popup.js sends a message chrome.runtime.onMessage.addListener((msg, _sender, sendResponse) => { switch (msg.action) { case 'ADD_EVENT': sendResponse(await addEvent(msg.type)); break; case 'UNDO': sendResponse(await undoLastEvent()); break; case 'GET_STATS': sendResponse(await getStats()); break; case 'EXPORT': sendResponse({ data: await exportData(msg.format) }); break; } return true; // Keeps the channel open for async replies });
⚠ Why return true? Chrome closes the message channel after a function returns. Since our storage operations are async (they take a moment), we need to return true to tell Chrome "wait, I'll reply later."

5. content.js — The Widget on Zendesk

🖼 Analogy: content.js is like a sticker you put on a window (the Zendesk page). It draws a little panel with colored circles on the page. It watches your mouse and reacts. It also talks to the brain (background.js) when you double-click.

How the Widget is Built

The widget is created entirely with JavaScript — no separate HTML file needed. We use innerHTML to write HTML as a string and inject it:

JavaScript
const widget = document.createElement('div'); widget.id = 'ztk-widget'; widget.innerHTML = ` <div id="ztk-header"> <div id="ztk-logo">TT</div> <!-- double-click to minimize --> </div> <button class="ztk-btn ztk-btn-red" id="ztk-btn-open"></button> <button class="ztk-btn ztk-btn-yellow" id="ztk-btn-new"></button> <button class="ztk-btn ztk-btn-blue" id="ztk-btn-team"></button> `; document.body.appendChild(widget); // Attach it to the page

Sending a Message to background.js

JavaScript
// When a double-click is confirmed, we fire this: chrome.runtime.sendMessage({ action: 'ADD_EVENT', type: 'open' }); // ↑ ↑ // what to do which button

The Collapse / Expand Feature

Double-clicking the TT logo simply toggles a CSS class called ztk-collapsed on the widget element. CSS then hides the buttons automatically:

JavaScript
isCollapsed = !isCollapsed; // flip true/false widget.classList.toggle('ztk-collapsed', isCollapsed); // Adds class "ztk-collapsed" when true, removes it when false

🎨 Analogy: If content.js builds the house out of bricks, widget.css paints it, decorates it, and adds the animations. Without CSS, the widget would just be grey boxes.

7. popup.html + popup.css + popup.js

📊 Analogy: When you click the TT icon in Chrome's toolbar, Chrome opens popup.html like a small window — like opening a mini website. popup.css styles it, and popup.js makes it interactive.

popup.html — The Blueprint

Every element you see in the dashboard has an id so JavaScript can find and update it:

HTML
<!-- The stat number for open tickets --> <div class="stat-value" id="stat-open">0</div> <!-- ↑ popup.js finds this by id and updates the number --> <!-- The chart canvas - Chart.js draws here --> <canvas id="main-chart"></canvas> <!-- Load chart library FIRST, then our code --> <script src="chart.min.js"></script> <script src="popup.js"></script>

popup.js — Fetching Stats and Updating the Screen

JavaScript
// 1. Ask background.js for the stats chrome.runtime.sendMessage({ action: 'GET_STATS' }, (response) => { stats = response; renderStats(); // Fill in the numbers renderChart(); // Draw the bar chart }); // 2. Fill in the numbers function renderStats() { const data = stats.today; // or stats.week / stats.month $('stat-open').textContent = data.open; // Update the "Open" number $('stat-new').textContent = data.new; // Update the "New" number $('stat-team').textContent = data.team; // Update the "Team" number } // $ is just a shortcut: function $(id) { return document.getElementById(id) }

Export to CSV — How Downloads Work

JavaScript
function triggerDownload(content, filename) { const blob = new Blob([content], { type: 'text/csv' }); // ↑ Blob = Binary Large Object = a chunk of data in memory const url = URL.createObjectURL(blob); // ↑ Creates a temporary web address pointing to that data chunk const a = document.createElement('a'); a.href = url; a.download = filename; a.click(); // Simulates a user clicking a download link URL.revokeObjectURL(url); // Cleanup: free the temporary address }

8. chart.min.js — Drawing Charts

📦 Analogy: chart.min.js is like a LEGO kit someone else designed. You don't need to know how they built it — you just use its instructions (the API) to build a chart. The .min means it's been "minified" — all spaces removed, variable names shortened so it loads faster.

How popup.js Uses Chart.js

JavaScript
const ctx = $('main-chart').getContext('2d'); // ↑ Gets a "drawing context" on the canvas element — like picking up a pencil chartInstance = new Chart(ctx, { type: 'bar', // Bar chart data: { labels: ['Mon', 'Tue', 'Wed', ...], datasets: [ { label: 'Open', data: [5,3,8,...], backgroundColor: 'rgba(255,107,107,0.85)' }, { label: 'New', data: [2,1,4,...], backgroundColor: 'rgba(255,217,61,0.85)' }, { label: 'Team', data: [1,2,3,...], backgroundColor: 'rgba(116,185,255,0.85)' } ] } }); // Chart.js does ALL the drawing — you just provide the numbers.
💡 Why is it bundled locally? If we loaded it from the internet (cdn.jsdelivr.net), Chrome would block it — extensions aren't supposed to make network requests for code. So we downloaded it once and stored it as a file inside the extension folder.

9. How the Files Talk to Each Other

📬 Analogy: Think of it like a post office system. content.js and popup.js are residents who write letters. background.js is the post office that receives letters, does work, and sends replies. They never visit each other's "house" directly — everything goes through messages.

Message Sending Pattern

JavaScript
// ── SENDER (content.js or popup.js) ────────────────────── chrome.runtime.sendMessage( { action: 'ADD_EVENT', type: 'open' }, // The letter (response) => { // The reply callback console.log(response.success); // Do something with the reply } ); // ── RECEIVER (background.js) ────────────────────────────── chrome.runtime.onMessage.addListener((msg, _sender, sendResponse) => { if (msg.action === 'ADD_EVENT') { addEvent(msg.type).then(result => sendResponse(result)); } return true; // Keep channel open });

Who Talks to Whom

1
content.js → background.jsSends ADD_EVENT when double-click detected. background.js saves it.
2
popup.js → background.jsSends GET_STATS when popup opens. background.js returns all aggregated totals.
3
popup.js → background.jsSends UNDO. background.js pops the last event and recalculates the day's totals.
4
popup.js → background.jsSends EXPORT. background.js returns all data as CSV or JSON string.
5
popup.js → Chart.jsNot a message — direct function call. popup.js calls new Chart() from chart.min.js which is loaded on the same page.

10. How Data is Saved Forever

🗃 Analogy: chrome.storage.local is like a filing cabinet bolted to the floor inside Chrome. It survives browser restarts, computer restarts, extension reloads — everything. The only way to remove data is to uninstall the extension or manually clear it.

Reading from Storage

JavaScript
chrome.storage.local.get(['events', 'dailyTotals'], (result) => { // Chrome fetches the data and gives it to our function const events = result.events ?? []; // ↑↑ // ?? means "if this is null/undefined, use this default instead" });

Writing to Storage

JavaScript
chrome.storage.local.set({ events: data.events, dailyTotals: data.dailyTotals }, () => { console.log('Saved!'); // Called after save is confirmed });

The Append-Only Rule

We never overwrite old events. We only ever push new ones onto the end of the array. This means history is always intact:

JavaScript
data.events.push({ type: 'open', timestamp: Date.now() }); // .push() adds to the END of the array — never removes anything // Date.now() = current time in milliseconds since Jan 1, 1970

11. How Double-Click Detection Works

⏱ Analogy: Imagine a bouncer at a door who counts knocks. If you knock twice within 350ms — that's a double-knock. If only one knock happens and 350ms passes without a second — it's ignored.
JavaScript
const DOUBLE_CLICK_DELAY = 350; // milliseconds (0.35 seconds) let clickCounts = { open: 0, new: 0, team: 0 }; let clickTimers = { open: null, new: null, team: null }; function handleClick(btn, type) { clickCounts[type]++; // Count this click (1st or 2nd) if (clickCounts[type] >= 2) { // ✅ DOUBLE CLICK — count the ticket! clickCounts[type] = 0; // Reset counter clearTimeout(clickTimers[type]); chrome.runtime.sendMessage({ action: 'ADD_EVENT', type }); } else { // First click — start a timer. If no 2nd click arrives in time → reset clickTimers[type] = setTimeout(() => { clickCounts[type] = 0; // ❌ Timed out — single click, ignore it }, DOUBLE_CLICK_DELAY); } }

12. The Full Journey of One Double-Click

Here's exactly what happens from the moment you double-click 🔴 to the moment the data is saved:

1
User double-clicks 🔴 Red button on Zendesk content.js detects 2 clicks within 350ms → confirmed double-click
2
Pulse animation fires (widget.css) JS adds class ztk-pulsing to the button. CSS keyframe animation runs. A +1 label floats upward.
3
Message sent to background.js chrome.runtime.sendMessage({ action: 'ADD_EVENT', type: 'open' })
4
background.js receives message Runs addEvent('open'). Gets current time. Builds dateKey like "2026-02-28".
5
Data is written to chrome.storage.local Pushes new event to events[]. Increments dailyTotals["2026-02-28"].open by 1.
6
Later: user clicks the TT icon → popup opens Chrome loads popup.html. popup.js immediately sends GET_STATS to background.js.
7
background.js calculates stats and replies Reads dailyTotals from storage. Sums up today / last 7 days / this month. Returns all of it.
8
popup.js renders the dashboard Updates number cards. Calls new Chart() using chart.min.js. Bar chart appears on screen. Done! ✅
